# grblHAL LPC1768 board skeleton

This directory contains a draft skeleton for adapting grblHAL to a custom LPC1768 controller for a 5-axis CNC/3D printer system.

The code is intentionally minimal and intentionally leaves many hardware-dependent values as placeholders. It is meant to be used as a starting point when integrating grblHAL (or a grblHAL-like codebase) into a custom board.

## Overview

The board is expected to include:
- LPC1768 controller
- 5 axes (X/Y/Z from the main LPC1768, A/B from a secondary MCU or extended step generator)
- microSD on SPI
- USB UART bridge (CH340) for firmware update and control
- TTL serial display (UART)
- limit/probe/estop inputs
- spindle PWM + direction + enable + tach
- coolant outputs
- SWD debug header and boot button

## Files
- `board.h` — board-level pin definitions and hardware mapping
- `my_machine.h` — compile-time feature flags and grblHAL config
- `driver_glue.c` — driver glue code; stubs to be filled in with actual hardware implementations
- `CMakeLists.txt` — minimal skeleton for building the driver as a library or submodule

## Important notes

- This is not a full ready-to-compile firmware. It is a baseline.
- To compile with grblHAL, integrate these files into the target `src` tree of `grblHAL/LPC176x` or a custom driver tree.
- The actual board pin mapping must be validated against the exact LPC1768 pinout and the chosen external step generator / second MCU.
- Step pulses for X/Y/Z are expected to be generated by LPC1768 timer hardware. A/B can be generated by a secondary MCU or by expanded timer resources if the board design supports it.

## Recommended integration path

1. Copy files into the target `src/` directory of your grblHAL fork.
2. Adjust the `board.h` pin numbers to match the final PCB routing.
3. Map UART/SPI pins to actual LPC1768 pins.
4. Validate with a logic analyzer against step pulse output.
5. Add SD card file system and display output logic.

# Example build flow

```
# from your grblHAL/LPC176x tree
mkdir build && cd build
cmake ..
make -j8
```

This skeleton expects the upstream grblHAL core and driver project to be present and configured.
